本期总览

本期材料将 Agent 的竞争重心从“模型权重”推进到“执行外壳”：长程任务的可靠性，更取决于上下文、工具、状态与观测如何被组织，而不只取决于模型本身有多聪明。DeepSeek Harness 的意义在于把这些运行时能力做成可替换、可回滚、可回放的基础设施；但开放的自修改能力仍必须由验证和治理闭环约束。

主题聚合

Agent 基础设施可组合运行时可观测性与治理

从模型产品到执行系统

Harness 被独立于模型产品线，说明生态控制点正下沉至任务执行层：工具调度、上下文注入、状态持久化、审批、重试和终止条件共同决定 Agent 是否能稳定完成真实任务。MCP 解决外部能力“怎么连”，Harness 则回答这些能力“如何被运行和控制”。

以插件实现可组合与可撤销

Cordis 把模型适配、工具、上下文、会话存储乃至 Agent Loop 都抽象为插件；不仅能随依赖动态重组，也强调卸载后撤销监听与副作用。运行时由此从固定框架变成可实验、可恢复的系统。

事件流将观测变成系统底座

仅追加事件流作为唯一事实来源，令上下文注入、工具调用与中间过程可被精确回放和归因。它对应知识库既有的 Trace-Native 思路：可观测性不是外围日志，而是可靠迭代的前提。

核心认知

  • Agent 能力是“模型 × 运行时”的乘积。同一模型在不同的上下文管理、工具循环和状态机制下，会表现出截然不同的任务上限。
  • 模块化的关键不只是扩展，而是可逆性。插件可卸载、事件可回放，才使运行时实验从一次性改动变成可控试验。
  • 效率优化也改变能力边界。PTC 以代码编排工具调用，减少模型—环境往返、上下文堆叠与 Token 成本；它不是单纯降本，而是在为更长链条的任务释放预算。

关键张力

自进化接口 vs. 可验证的进化结果

创造模式允许运行时自指和自修改，但“能够修改”不等于“能够变好”。若没有确定的验证函数、回归测试和环境反馈，系统容易将局部补丁误判为进步，甚至累积为退化。

开放插件生态 vs. 生产治理

插件接触文件、执行环境与会话数据，扩展性同时扩大权限、供应链和依赖冲突的攻击面。生产可用性取决于隔离、权限边界、审计与版本治理能否跟上开放速度。

本期判断：最值得投资的不是让 Agent 更自由地行动，而是让每一次行动、修改与失败都能被约束、解释并安全地撤回。

认知变化

此前对 Agent 的关注更易落在协议接入与模型能力；本期进一步明确了层级差异：协议解决连接，Harness 负责控制，事件流提供事实与追责基础。由此，“可观测性”从辅助诊断能力上升为支持自适应与治理的共同底座。

待思考问题

  • 自修改运行时应采用哪些可量化的验证门：任务成功率、成本上限、安全策略，还是可回放的因果归因？
  • 插件的权限模型如何同时满足快速组合与最小权限，尤其面对文件系统、Shell 与长期会话数据？
  • PTC 降低交互轮次后，如何保留足够的可解释性与人工介入点，避免效率换来不可审计的黑箱？
  • 若事件流是唯一事实来源，事件模式、隐私脱敏与长期存储成本应如何设计，才能真正支撑跨周期学习？
