主题二 · 世界模型四类分类法 ×「出口校验」：为什么不能信任模型"心算"物理

来源：03-18《别再乱叫"世界模型"了：一张图分清 4 类》重读（08-28 触碰） × 08-27 ROSS 五层 / 9 纵 4 横
  • 四条分类线：世界模型（动力学，预测世界如何演化）、空间智能（3D 结构，无 action 条件）、行为模型（策略，预测最优动作）、代理世界模型（LLM 内部语义近似）。
  • 关键连接 1：LLM 只是「代理世界模型」——只能覆盖"语言能描述的那部分现实"，是物理动力学层的语义子集。这正是 ROSS 出口校验结构性的原因：语义正确 ≠ 物理安全，模型"心算"物理天然缺一层，靠模型自觉兜底是幻想。
  • 关键连接 2：行为模型（直接给动作的策略，如 Wayve / Physical Intelligence）在四类中最贴近执行、最危险——对应 ROSS 对 VLA 的处理：不改基座、外挂 VLA-Stem 安全层，策略越直接，越需出口校验。
  • 关键连接 3：世界模型无法暴力 scaling（物理数据难采集、长尾稀疏），需表示层（潜空间而非 next token）+ 目标函数（物理约束）+ 架构（注意力+线性层）三联动——即模型侧短期内补不上物理层，故毫秒级硬安全必须外置给控制器，Harness 是"物理世界模型不成熟"时代的补偿架构。
  • 对 2127 的落点：车端 harness 应显式声明自己依赖哪种世界模型——若用 LLM 语义层（代理模型），就必须配 CLMASP 式形式化校验与执行侧物理兜底；若要真物理层的动力学预测，需引入行为/动力学模型与仿真器。

主题三 · 具身赛道 2026-2028 三阶段 × Token 终局：给"终局"装上时间表

来源：08-20《具身智能赛道周期与 2026–2028 窗口期研判》重读（08-28 触碰） × 08-25《Token 终局》
  • 三阶段演进：① 2026下-2027上 工程幻灭与微闭环死斗（窄场景验证 MTBF、出清尾部）→ ② 2027中-2027下 基座模型统一 + 硬件白菜化（开源大脑普及、整机 10-15 万）→ ③ 2028 巨头收割与规模化上岗（窗口关闭，回归制造 / 生态 / 责任闭环）。
  • 交叉验证 1：第二阶段"基座模型统一"= 08-25 判断的"模型架构开源趋同"在具身域的镜像——算法壁垒平民化后，稀缺性转移到调度入口 + 责任边界（谁掌握运行时计费与编排、谁兜物理责任）。两篇独立来源互相印证。
  • 交叉验证 2：第三阶段"责任兜底体系 / 百万工时无事故率"= "责任边界 = 市场壁垒"在 2028 年的产业落点——Token 终局不是悬空推演，2028 就是验收点。
  • 交叉验证 3：08-25 修正"硬件平台化快、但通用智能最难（单步需 99.78% 成功率）"——与三阶段吻合：硬件白菜化在②阶段发生，而"通用智能 + 责任闭环"要到③阶段才见分晓，两件事不同速，中间的 2026-2028 正是卡位责任体系的时间窗。
  • 对 2127 的落点：2027 中开源基座普及 + 硬件 10-15 万是确定性节点——车厂若只做硬件平台，2027-2028 即被 Token 化榨干毛利；卡位"车的智能调用入口 + 责任边界"须在 2027 前完成架构与责任体系布局。

2核心认知

本轮把旧笔记拉回主线后新增 / 强化、且经受第三轮检验的判断。

出口校验是结构性必然，不是保守主义本轮新增

LLM 只是"代理世界模型"（语义层子集），物理动力学层天然缺失——因此"模型输出 → 外层安全校验"不是谨慎选择，而是认知结构决定的唯一选项。ROSS 的 Safe-BeAl / VLA-Stem 是这一结构在工程上的必然表达。

Harness = "物理世界模型不成熟"时代的补偿架构本轮新增

世界模型四类笔记给出模型侧路径（表示层 + 物理约束 + 混合架构），但物理数据 scaling 难是结构性问题、短期无解。故在模型真正学到物理之前的整个窗口期，毫秒级硬安全、出口校验、执行补偿必须由 harness 外置承担。

Token 终局有明确时间表：2028 是验收点本轮强化

具身窗口期研判与 Token 终局是两篇独立来源，却在时间轴上自洽：2027 基座开源 + 硬件白菜化（架构与硬件同时不稀缺）→ 2028 责任兜底定胜负。战略判断从"终局是什么"推进到"终局何时、以什么指标验收"。

决策频率分层经受三个独立角度检验第三轮仍在

ROSS 的毫秒硬安全 / 持续监督 / 任务级判断 ←→ 数字 Agent 的高频校验 vs 低频规划 ←→ 世界模型"慢思考 ≠ 实时控制"。三个独立来源指向同一结构：模型不参与毫秒级决策，安全兜底运行在更高频率上。

Infra 是漂移的补偿机制第三轮仍在

推理栈输出漂移（Level1Techs）、语义层 vs 物理层偏差（世界模型分类）本质同类：模型输出不稳定是物理事实，L1 网关 Fallback + L7 评测门禁 + L8 Trace + 出口校验是把"不稳定"当工程输入而非事故。

3关键张力

旧笔记重读暴露出的、仍未定论的对立。

语义正确 vs 物理正确：LLM 说得对，就一定做得对？

代理世界模型能给出语言层面正确、物理层面危险的动作（"水往低处流"说得对，却推不出流场细节）。张力不在"要不要管"，而在校验成本：出口校验每多一层，都在延迟与吞吐上付费——校验的粒度与成本如何与风险匹配，仍是开放设计问题。

硬件白菜化 vs 通用智能难：平台趋同快，大脑趋同慢

三阶段研判说 2027 硬件降至 10-15 万、基座开源；08-25 测算单步需 99.78% 成功率才撑得起长程任务。硬件 + 算法权重同时"不稀缺"时，仍缺的 0.22% 恰恰是责任边界的价值所在——也说明"卖被信任的调度权"的溢价空间能撑多久，取决于通用智能缺口何时被补上。

外置安全层 vs 系统效率：多一层校验，多一分延迟

出口校验 / 形式化补全（CLMASP）在快速响应场景可能与执行时延冲突。ROSS 用"时间尺度分层"回避了模型参与毫秒级决策，但任务级判断的偏离阈值、校验预算仍未量化——这是五层框架走向工程化的核心细节。

PR 口径 vs 独立验证：框架可信，数据存疑（第三轮不变）

ROSS 赛绩与工程成熟度全为自报、无第三方审计；世界模型四类为商业文章分类法。两篇都作为"思考框架"引用，量化结论均待独立来源核验——第三轮验证仍未找到第三个独立样本。

5待思考问题

笔记标注的"待核验 / 局限"与本轮重读产生的新问题。

1. 车端 harness 应显式声明依赖哪类世界模型？

若是"代理世界模型"（LLM 语义层），必须配 CLMASP 式形式化校验 + 物理兜底；若要真物理层预测，需引入动力学模型 / 仿真器作为校验基准。2127 白空间清单里应增加"世界模型类型声明"一栏，把四分类法落成工程决策。

2. "语义层缺口"是否可被多模态 / 合成数据补上？

三篇笔记的判断一致偏悲观：物理数据 scaling 难是结构性的，合成数据信息上界受初始真实数据约束。但 World Labs / Cosmos / V-JEPA 2 连出的节奏值得跟踪——若某条技术路径突破，harness 外置安全的必要性会否被模型侧吸收？这是 2026-2028 需要持续盯的变量。

3. 2027 / 2028 两个时间节点，知识库用什么指标跟踪？

窗口期研判给出了可观测里程碑：MTBF 与连续执行成功率（>95% 淘汰线）、基座开源事件、整机成本是否落到 10-15 万、百万工时无事故率监管文件。是否值得建立"产业周期指标清单"并把相关新素材自动归位到三阶段坐标里？

4. 校验成本如何量化？（延续上期）

出口校验 / 任务级偏离判断的延迟与吞吐开销、误干预率如何控制？五层框架要变成工程，需要一个"校验预算"模型——哪些层必须毫秒级、哪些可异步，仍是空白。

5. 第三个独立样本仍未找到（延续）

数字框架 + 物理实践 + 产业周期时间表已构成三角互证，但都非第三方审计来源。下一个样本值得主动检索：车企 ASIL-D harness、大厂 Agent 平台安全架构、或具身基座公司的责任承保条款——第三点独立落定，主线即稳固。
